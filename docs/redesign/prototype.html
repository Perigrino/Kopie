Kopie redesign prototype v2 · light + dark · mechanics from Airpisode · palette of its own

Kopie in Ember.

Kopie's own colours now — a tangerine→raspberry gradient pulled straight out of Kopie's existing app icon, which stays exactly as it is. Airpisode supplied the mechanics: near-black canvas with two soft glows, translucent cards with a gradient hairline, capsule chips, gradient tiles, one spring vocabulary. The navigation does not move — it stays on the left. Both appearances are real: light is warm paper with white surfaces, dark is the near-black canvas — same components, same accent, one switch at the top right. Click any palette in section 0 to preview all four across the whole board.

v2 changes — as requested

  • New palette, Kopie's own. No violet, no orchid. Default is Ember · Rose (#E9622F → #C42A63), read off the peach→rose gradient already in Kopie's icon. Three alternates are previewable — click and the whole board repaints.
  • The app icon is untouched. Every place the old prototype invented a mark now renders the shipped assets/icon-sources/design10.png exactly as it is. I did not redraw, recolour, or re-shadow it. The menu-bar item uses the shipped KopieMenuTemplate.png (a template image, so it is inverted the way macOS tints one on a dark bar — the file itself is unchanged).
  • The nav stays on the left. The floating dock is gone. Kopie keeps its sidebar, in place, in the same order: All · Text · Images · Files · Today · Favorites · Pinned · Sensitive, with Settings pinned to the bottom.
  • Light and dark are both first-class. Every surface is a token with two values, so the whole app — windows, popover, settings, onboarding, states — swaps between the near-black canvas and warm paper (#FBF8F4) without a single component branching on appearance. Use the switch at the top right; the pair in section 0 shows both at once.

6 How this would port back into SwiftUI

For later — no code has been written. This is the mapping, so the lift is mechanical rather than a redesign-by-accident.

new UI/Theme.swift
Airpisode's Theme mechanics — canvas, cardBackground(cornerRadius:), chip, gradient — carrying Kopie's own two stops.
new UI/Motion.swift
smooth / quick / gentle springs, .appear(), .hoverLift().
UI/Components.swift
BreathingBackground → Theme.canvas; DS.pad and EmptyStateView stay; empty state gains the gradient CTA.
UI/MainView.swift
Sidebar stays put and keeps its order; selection becomes a gradient pill; the count badges are new.
UI/HistoryRow.swift
Row becomes a card at radius 14; the 40×40 glyph becomes a 44×44 tile; hover actions unchanged.
UI/DetailsPanel.swift
MetaGrid card + gradient primary Copy button; the segmented control becomes filled chips.
UI/PopoverView.swift
Same 440 × 360 dimensions; row chrome swaps to the card style.
UI/LandingView + OnboardingView
Five steps unchanged; canvas behind, gradient buttons, app icon as shipped.
UI/Settings/*.swift
Six tabs unchanged; grouped cards, gradient toggles and active tab.
UI/Theme.swift — light / dark
Each token resolves per colorScheme: canvas, card fill, hairline, row hover, field and toast all have a paper value. No component asks which appearance is active.
AppIcon.swift, AppIconResolver
Not touched. Only GlobalActions-level chrome is restyled.
Sensitive rows
Deliberately outside the tint system — orange stays orange, never gradient.
