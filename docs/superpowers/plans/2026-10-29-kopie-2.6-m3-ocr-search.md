## Goal
On-device OCR never blocks the capture poll loop, gets backfilled for existing history with real progress, and is copyable as text from the action menu for any image item with OCR text.

## Gap analysis (facts verified from source)
- **Already implemented — do NOT duplicate:** S-020's "OCR indexed on capture + searchable" pipeline exists end-to-end. `CapturePipeline.process` (lines 114-119) writes `item.ocrText = ImageTextRecognizer.recognizeText(in:)`; `ClipStore.insert` persists `ocr_text` column and indexes it via `searchTokens(for:)`; `ClipStore.match` matches `item.ocrText` case-insensitively; the Settings toggle + `CaptureConfig.ocrImages` already gate it.
- **The real problem (S-020 breach):** line 114-119 runs `VNRecognizeTextRequest` **synchronously on the calling thread**, which per M2 Task 1 is the main tick thread → poll-loop backpressure. `ImageTextRecognizer.recognizeText` doc even says "callers should invoke off the main thread." Fix: defer the Vision call off the hot path, write the result back async.
- **No backfill service exists:** S-021 needs a new `OcrBackfill` (KopieCore/Retention/) mirroring `RetentionJob`'s shape (init(store:), synchronous run on a serial scheduler, idempotent + resumable). `ClipStore` already has a `backfillSearchIndex()` precedent (line ~160) to mirror.
- **No "Copy Text" action exists:** S-022 needs it in `DetailsPanel.actions` (line 580) and/or `ContextMenuBuilder`. `ClipboardItem.ocrText` + `isSensitive`/`sensitiveKind` already exist.
- **Tests:** `OCRPipelineTests.swift` (100 LOC, XCTest) covers capture→searchable, disabled flag, windowed fallback, and DB migration. Its `pngWithText(_:)` fixture renders 36pt bold text on a 360×120 white NSImage → PNG. New M3 tests use **Swift Testing** (`import Testing`, `@testable import KopieCore`), and may reuse `pngWithText` via a test-helper shim in the new suite — never modify the existing XCTest file.
- **App-level entry:** `AppState` (Sources /Kopie/AppState.swift line ~35 `let store: ClipStore`).

## Architecture
- OCR stays in KopieCore (`ImageTextRecognizer` already pure). Add a serial `captureQueue`-style `.userInitiated` queue owned by `AppState` so Vision work never touches the main tick thread and the store write-back happens on a single worker thread (ClipStore is single-thread-bound until S-031 FULLMUTEX).
- Backfill: a new `OcrBackfill` enum/struct in `Sources/KopieCore/Retention/OcrBackfill.swift`, callable from `AppState`, with a public progress type (`OcrBackfill.Progress { done, total, isComplete }` and a Combine/published bridge done in Task 3 for the UI).
- "Copy Text" action: `DetailsPanel` + `ContextMenuBuilder` only for `item.kind == .image && !item.isSensitive && !(item.ocrText?.isEmpty ?? true)`.

**Interfaces**
- `CapturePipeline.process` currently `public func process(_ content: CapturedContent, config: CaptureConfig, now: Date = .now) -> CaptureResult` (lines 26-142). The plan adds `public func processWithPendingOCR(_ content: CapturedContent, config: CaptureConfig, now: Date = .now) -> (CaptureResult, Data?)` that does the full validation/build/insert but sets `item.ocrText = nil` and returns the tuple `(CaptureResult, ocrData: Data?)`. `process` is then refactored to delegate to `processWithPendingOCR` and perform Vision **synchronously** on the returned `ocrData` (if any) followed by synchronous `store.updateOCR(id, text)` so that existing callers (`OCRPipelineTests`) see identical synchronous behavior. AppState's handler in Task 1 switches to calling `processWithPendingOCR` + dispatching Vision to the serial OCR queue.
- `ClipStore.updateOCR(_ id: Int64, _ text: String?) -> Bool`: if `text == nil { return true }`, verify row `kind == .image`, `UPDATE clipboard_items SET ocr_text = ? WHERE id = ?`; on success delete old `search_index` rows for id and re-index via `indexTokens(searchTokens(for: item), for: id)`; return `changed > 0`.
- `AppState.ocrQueue: DispatchQueue = DispatchQueue(label: "com.kopie.ocr", qos: .userInitiated)`. Handler closure uses `processWithPendingOCR`, captures the returned `ocrData`, then `ocrQueue.async { let text = ImageTextRecognizer.recognizeText(in: data); DispatchQueue.main.async { store.updateOCR(id, text); NotificationCenter.default.post(name: .kopieStoreChanged, object: nil) } }`.
- Add to `CaptureResult` a helper: `var capturedID: Int64? { if case .captured(let id) = self { return id }; return nil }` (used by handler to get the ID for `updateOCR`).

```swift
// In AppState.init, replace the monitor handler closure:
handler: { [weak pipeline, weak self] c in
    guard let pipeline, let self else { return }
    let cfg = SettingsStore.shared.captureConfig
    let (r, ocrData) = pipeline.processWithPendingOCR(c, config: cfg)

        }

    if case .captured = r { NotificationCenter.default.post(name: .kopieStoreChanged, object: nil) }
}
```

### Task 2: OCR backfill service + tests (S-021 core)

**Files**
- Create: `Sources/KopieCore/Retention/OcrBackfill.swift` (the service; mirrors `RetentionJob` shape — `public enum OcrBackfill { public static func backfill(store:store, batchSize: Int = 50, now: Date = .now) -> OcrBackfill.Result }`)
- Create: `Tests/KopieCoreTests/OcrBackfillTests.swift` (Swift Testing)
- Modify: `Sources/KopieCore/Storage/ClipStore.swift` (add `imagesNeedingOCR(limit:)` query returning `[(id: Int64, imageRelPath: String)]` of image rows with `ocr_text IS NULL OR ocr_text = ''` AND `is_sensitive = 0`, ordered by `created_at ASC`; backfill service uses passed `ClipWriter.imageData(relPath:)` to fetch bytes for Vision).
- Modify: `Sources/KopieCore/Support/SettingsStore.swift` (new Bool key `ocrBackfillAuto` default true + boolKeys; OR keep Task 3 for the scheduler — decide: this task ships the *service*, Task 3 ships the *scheduler* + UI).

**Design**
- `OcrBackfill.backfill(store:, batchSize:)`: scans for image rows with null/empty ocr, runs `ImageTextRecognizer.recognizeText(in:)` for each (on the caller's thread — the scheduler in Task 3 provides the background thread), writes back via `store.updateOCR`, returns `Result { done, total, isComplete, error: String? }`. Idempotent: rows already ocr'd are skipped. Resumable: re-query each batch is naturally resumable by row id cursor.
- `ClipWriter` ownership: `ClipStore.init(dir:crypto:)` has no writer. Add a `ClipWriter?` param to a new init overload OR pass the writer into `backfill`. **Decision:** backfill takes an injected `ClipWriter` like `CapturePipeline` does — clean, no state in ClipStore. The service reads image bytes via `writer.imageData(relPath:)` (ClipWriter has that) after resolving relPath from the row. Actually `ClipStore` does NOT expose image relPath for a row without the full item... `get(id:)` returns a `ClipboardItem` which has `imageRelPath`. So backfill: `for row in imagesNeedingOCR { if let item = store.get(row.id), let rel = item.imageRelPath, let data = try writer.imageData(relPath: rel) ... }`. Wait — `writer.imageData` requires the file to exist. For image items it will.
- So service signature: `OcrBackfill.backfill(store:, writer:, batchSize:, now:)` → `OcrBackfill.Result`.

**Tests**
1. `test_backfillIndexesAllImagesInBatch` — insert 3 image items with nil ocr via pipeline, run backfill, assert all 3 now have non-nil ocrText searchable.
2. `test_backfillIsIdempotent` — run twice; second run `done == 0`, no re-write, still searchable.
3. `test_backfillReachesCompletionAndReportsProgress` — 100 synthetic images, assert `isComplete == true` when done after N batches and `total` stable, `done == total` at end.
4. `test_backfillSkipsAlreadyOCRed` — pre-tag 2 rows with ocrText, leave 3 null; assert only 3 processed.
5. `test_backfillDoesNotOCRDeleteFiles` — backfill on 5 images leaves their image files present (count via writer/imageData succeeding).

**Steps**
- Step 1 write tests first; `--filter OcrBackfillTests` → fail.
- Step 2 implement; `swift test` all green; `swift build -c release`.
- Step 3: `git commit -m "feat(ocr): idempotent backfill for pre-existing image history (S-021)"` — stage `OcrBackfill.swift`, `ClipStore.swift`, `OcrBackfillTests.swift`, `SettingsStore.swift`? (only if a setting ships here). **Note:** keep settings in Task 3 to avoid coupling. Stage: `OcrBackfill.swift`, `ClipStore.swift`, `OcrBackfillTests.swift`.
